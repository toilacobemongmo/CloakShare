Technical Monograph & Architecture Guide

Giải Phẫu Toàn Diện Dự Án CloakShare

Khung kiến trúc trao đổi tệp tin lai ghép (Hybrid Cryptosystem) phi tập trung, hiệu năng cao và tuyệt đối không lưu vết (Zero-Trace / Zero-Disk Persistence).

01. Bức Tranh Tổng Quan & Tôn Chỉ

Trong kỷ nguyên số, các dịch vụ truyền tải và lưu trữ tệp truyền thống (như Google Drive, Telegram, WeTransfer) luôn tồn tại ba rủi ro bảo mật cốt tử:

  • Lưu vết trên đĩa cứng (Disk Persistence): Dữ liệu tạm (temp files), bộ nhớ đệm (disk cache) hoặc log hệ thống lưu trên máy chủ trung gian rất dễ bị trích xuất qua điều tra số (Digital Forensics).
  • Giám sát siêu dữ liệu (Metadata Surveillance): Nhật ký truy cập (Access Log) ghi lại dấu vết ai gửi cho ai, thời gian truyền, kích thước và định danh gói tin.
  • Phụ thuộc cơ quan cấp phát chứng chỉ tập trung (Centralized CA): Kiến trúc PKI truyền thống phụ thuộc vào bên thứ ba (CA), dễ bị tấn công mạo danh (Man-In-The-Middle) hoặc thu hồi/ép buộc.
Tôn Chỉ Thiết Kế Của CloakShare "Tuyệt đối không lưu vết trên đĩa (0 Disk Writes), mã hóa lai chuẩn FIPS-197/RFC 8017 đạt thông lượng tối đa, và phi tập trung hóa danh tính khóa công khai trên EVM Blockchain."

02. Ba Trụ Cột Kiến Trúc Cốt Lõi

1. Lõi Mật Mã C Native

AES-128-CBC + PKCS#7 bằng C thuần FIPS-197 (>580 MB/s), RSA-OAEP 2048-bit bọc Session Key, và RSA-PSS ký số toàn vẹn.

2. dPKI Blockchain

Smart Contract EVM ánh xạ Address -> RSA Public Key PEM, kèm cơ chế Local Safe-Mode Fallback tự động khi offline node.

3. Zero-Log RAM Broker

Lưu trữ 100% trên heap RAM, tắt access log Uvicorn, xác thực ví EIP-191, tự hủy Burn-After-Read & TTL, ghi đè byte 0x00.

2.1. Lõi Mật Mã Lai C-Core Hiệu Năng Cao

Hệ thống sử dụng mô hình Hybrid Cryptosystem: Tệp tin kích thước lớn được mã hóa bằng thuật toán đối xứng tốc độ cao (AES), trong khi khóa phiên (Session Key) 128-bit được bọc bằng thuật toán bất đối xứng an toàn (RSA).

  • Thuật toán AES-128-CBC (core/aes128.c): Thực thi 10 vòng biến đổi (SubBytes, ShiftRows, MixColumns, AddRoundKey) và sinh lịch trình khóa KeyExpansion chuẩn FIPS-197. Chế độ CBC sử dụng IV ngẫu nhiên 16 bytes.
  • Đệm PKCS#7 An Toàn (core/padding.c): Tuân thủ RFC 5652. Nếu dữ liệu tròn bội số của 16 bytes, bắt buộc thêm khối đệm nguyên vẹn 16 bytes 0x10. Hàm pkcs7_unpad duyệt kiểm tra thời gian hằng số (Constant-Time), loại bỏ chênh lệch thời gian rò rỉ kênh kề chống Padding Oracle Attack.
  • Bọc khóa RSA-OAEP 2048-bit (engine/rsa_envelope.py): Sử dụng hàm băm SHA-256 và hàm mặt nạ MGF1. Cung cấp tính an toàn toán học cao nhất IND-CCA2.
  • Ký số toàn vẹn RSA-PSS (engine/signer.py): Chèn chuỗi muối ngẫu nhiên (Salt 32 bytes). Đạt chuẩn kháng giả mạo hiện sinh EUF-CMA: Sai lệch dù chỉ 1 bit bản mã cũng bị phát hiện và từ chối ngay.

2.2. Hạ Tầng Khóa Công Khai Phi Tập Trung (dPKI)

Smart Contract contracts/dPKIRegistry.sol xóa bỏ hoàn toàn nhu cầu về CA trung gian:

Solidity (EVM) - dPKIRegistry.sol 
mapping(address => string) private _publicKeys;

function registerPublicKey(string calldata publicKeyPem) external {
    require(bytes(publicKeyPem).length > 0, "Public key cannot be empty");
    _publicKeys[msg.sender] = publicKeyPem;
    emit PublicKeyRegistered(msg.sender, publicKeyPem);
}

function getPublicKey(address user) external view returns (string memory) {
    return _publicKeys[user]; // Mọi người tra cứu miễn phí 0 Gas!
}

Khi môi trường offline hoặc chưa bật node RPC, engine/dpki_client.py tự động kích hoạt Local Safe-Mode Fallback, chuyển sang bộ nhớ cache cục bộ an toàn để không bao giờ làm gián đoạn trải nghiệm người dùng.

2.3. Máy Chủ Đệm Zero-Log In-Memory RAM Staging

Được xây dựng trên nền tảng FastAPI/Uvicorn với cam kết kỹ thuật bất di bất dịch:

  • Vô hiệu hóa Access Log: logging.getLogger("uvicorn.access").disabled = True để URL chứa tx_id không bị ghi ra ổ cứng.
  • Tuyệt đối 0 Disk Writes: Payload chỉ nằm trong từ điển RAM (bytearray trong broker/memory_store.py).
  • Ghi đè byte 0x00 (Memset Zeroize): Hàm _wipe() duyệt qua từng ô nhớ và gán val[i] = 0 trước khi xóa tham chiếu.
  • Tự hủy kép: Tự hủy ngay sau khi đọc (Burn-After-Read) hoặc tự động dọn sạch sau khi hết hạn TTL qua vòng lặp ngầm 5 giây.

03. Luồng Dữ Liệu Toàn Trình Đầu-Cuối (E2E)

Sơ đồ tương tác từng bước từ Alice (Người gửi) qua trạm đệm RAM Broker tới Bob (Người nhận): 

+--------------------+        +----------------------+        +--------------------+
|  ALICE (SENDER)    |        |  BROKER (RAM HEAP)   |        |   BOB (RECEIVER)   |
+--------------------+        +----------------------+        +--------------------+
          |                              |                              |
  1. Tra cứu dPKI                        |                              |
     Bob_Address -> Bob_PubKey           |                              |
          |                              |                              |
  2. Tạo K_session & IV                  |                              |
  3. AES-128-CBC mã hóa File             |                              |
  4. RSA-OAEP bọc K_session              |                              |
  5. RSA-PSS ký Ciphertext               |                              |
          |                              |                              |
  6. POST /api/v1/stage ---------------->|                              |
     (tx_id, IV, Cipher, Key, Sig)       | Lưu trên Heap RAM            |
                                         | 0 Lần Ghi Đĩa                |
                                         | Bật đếm ngược TTL            |
                                         |                              |
                                         |<--- 7. GET /retrieve/{tx_id} -
                                         |        Headers: X-Wallet     |
                                         |                 X-Timestamp  |
                                         |                 X-Signature  |
                                         |                              |
                                         | 8. Xác thực ví EIP-191       |
                                         |    Kiểm tra |now - ts| <= 60s|
                                         |    (Chống Replay Attack)     |
                                         |                              |
                                         |---> Trả về Payload ---------->
                                         |                              |
                                         | 9. BURN-AFTER-READ:          |
                                         |    Ghi đè 0x00 lên RAM       |
                                         |    Xóa sạch khỏi Heap        |
                                         |                              |
                                                                        | 10. Xác thực RSA-PSS
                                                                        |     (Dữ liệu nguyên vẹn)
                                                                        | 11. Mở bọc RSA-OAEP
                                                                        |     (Lấy K_session)
                                                                        | 12. AES-128-CBC giải mã
                                                                        |     (Lấy tệp gốc!)
Cơ Chế Chống Replay Attack (Tấn Công Phát Lại) Bob bắt buộc phải ký chuỗi thông điệp có timestamp hiện tại. Nếu kẻ xấu trên mạng chặn bắt được gói tin HTTP Headers này và phát lại sau 60 giây, Broker sẽ lập tức từ chối với mã lỗi HTTP 401 Unauthorized.

04. Bản Đồ Mã Nguồn Chi Tiết

05. Ma Trận Phòng Thủ Mối Đe Dọa STRIDE

Mối Đe Dọa (STRIDE) Nguy Cơ Tiềm Ẩn Giải Pháp Kỹ Thuật Trong CloakShare
S - Spoofing (Mạo danh) Kẻ xấu nhận vơ là người nhận để rút trộm tệp Bắt buộc chữ ký ví Web3 EIP-191 khớp với địa chỉ recipient.
T - Tampering (Giả mạo) Can thiệp, sửa đổi dữ liệu bản mã trên đường truyền Chữ ký xác suất RSA-PSS (SHA-256). Lệch 1 bit bị từ chối giải mã ngay.
R - Repudiation (Chối bỏ) Người gửi chối trách nhiệm đã gửi tài liệu nhạy cảm Chữ ký được tạo bằng Private Key độc quyền của người gửi (Tính bất biến).
I - Info Disclosure (Lộ lọt) Bị nghe lén mạng hoặc dump bộ nhớ máy chủ Mã hóa lai kép AES-128 + RSA-OAEP; Broker tự hủy và ghi đè byte 0x00.
D - Denial of Service (Từ chối DV) Bơm dữ liệu rác làm tràn bộ nhớ RAM Broker Thời gian sống TTL ngắn hạn (mặc định 60s), luồng nền tự động dọn sạch mỗi 5s.
E - Elevation of Priv (Leo thang) Người ngoài can thiệp quyền Admin của máy chủ Broker phi trạng thái, phân quyền phân tán theo ví; không có backdoor Admin.

06. Hướng Dẫn Vận Hành & Trải Nghiệm

Các lệnh cơ bản để khởi chạy và kiểm chứng toàn bộ hệ thống:

1. Chạy nhanh kịch bản kiểm chứng mã hóa cục bộ 
python demo_full_flow.py
2. Chạy toàn bộ 35 bài kiểm thử tự động (Pytest) 
python -m pytest tests/ -v
3. Khởi động Máy chủ Zero-Log Broker (Cổng 8000, tắt access log) 
python -m uvicorn broker.main:app --port 8000 --no-access-log
4. Khởi chạy Giao diện Người dùng Hiện đại (Streamlit) 
python -m streamlit run ui/app.py
