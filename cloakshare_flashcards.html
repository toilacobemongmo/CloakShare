Đặc Tả Kỹ Thuật Chuyên Sâu CloakShare

Phân tích toán học mật mã, cơ chế byte/bit, cấu trúc con trỏ C FIPS-197, bytecode EVM và kỹ thuật dọn sạch bộ nhớ vật lý.

01. Lõi Thuật Toán AES-128 & Toán Học Galois Field

Lõi mã hóa trong core/aes128.c hiện thực hóa tiêu chuẩn NIST FIPS-197 với kích thước khóa 128-bit (16 bytes), chia khối dữ liệu thành ma trận trạng thái State $4 \times 4$ byte.

1.1. Phép nhân trên trường Galois $GF(2^8)$

Mọi phép tính trong tầng khuyếch tán MixColumns được thực hiện trên trường hữu hạn $GF(2^8)$ với đa thức bất khả quy chuẩn: 

m(x) = x^8 + x^4 + x^3 + x + 1   (Dạng nhị phân: 0x11B)

Hàm nhân gmul(a, b) được tối ưu hóa trực tiếp bằng toán tử dịch bit và phép XOR modulo 0x1B:

core/aes128.c - Phép nhân Galois Field 
static inline uint8_t gmul(uint8_t a, uint8_t b) {
    uint8_t p = 0;
    for (int i = 0; i < 8; i++) {
        if (b & 1) p ^= a;
        uint8_t hi = a & 0x80;
        a <<= 1;
        if (hi) a ^= 0x1b; // Modulo đa thức m(x)
        b >>= 1;
    }
    return p;
}

1.2. Mở rộng khóa (KeyExpansion)

Từ khóa bí mật gốc 16 byte ($W[0..3]$), thuật toán sinh ra lịch trình khóa gồm 11 Round Keys ($11 \times 16 = 176$ bytes):

  • Nếu $i \pmod 4 == 0$: $W[i] = W[i-4] \oplus \text{SubWord}(\text{RotWord}(W[i-1])) \oplus \text{Rcon}[i/4]$
  • Nếu $i \pmod 4 \ne 0$: $W[i] = W[i-4] \oplus W[i-1]$

1.3. Bốn Phép Biến Đổi Trong 10 Vòng Lặp

  1. SubBytes: Thay thế phi tuyến từng byte qua bảng tra S-Box (kết quả từ phép nghịch đảo nhân trong $GF(2^8)$ kết hợp biến đổi affine).
  2. ShiftRows: Dịch vòng trái các hàng: Hàng 0 không dịch; Hàng 1 dịch 1 byte; Hàng 2 dịch 2 byte; Hàng 3 dịch 3 byte.
  3. MixColumns: Nhân ma trận MDS (Maximum Distance Separable) cố định: 
    [ s'0,c ]   [ 02  03  01  01 ] [ s0,c ]
[ s'1,c ] = [ 01  02  03  01 ] [ s1,c ]
[ s'2,c ]   [ 01  01  02  03 ] [ s2,c ]
[ s'3,c ]   [ 03  01  01  02 ] [ s3,c ]
    Lưu ý kỹ thuật: Tại vòng thứ 10 (vòng cuối cùng), phép biến đổi MixColumns bị bỏ qua nhằm đảo ngược giải mã đối xứng hoàn hảo!
  4. AddRoundKey: XOR ma trận trạng thái với Round Key tương ứng của vòng đó.

1.4. Chế độ Liên Kết Khối (CBC Mode)

Phương trình mã hóa và giải mã khối CBC với Vector khởi tạo ngẫu nhiên $IV$ ($16$ bytes):

$$C_0 = \text{AES}_K(P_0 \oplus IV), \quad C_i = \text{AES}_K(P_i \oplus C_{i-1})$$ $$P_0 = \text{AES}^{-1}_K(C_0) \oplus IV, \quad P_i = \text{AES}^{-1}_K(C_i) \oplus C_{i-1}$$

02. Cơ Chế Đệm Khối PKCS#7 & Constant-Time Unpad

Theo chuẩn RFC 5652, mọi bản rõ trước khi đưa vào AES-CBC bắt buộc phải đạt độ dài là bội số của 16 bytes.

2.1. Quy tắc tính Padding Byte

$$pad\_val = 16 - (in\_len \pmod{16})$$
Độ dài bản rõ ban đầu Giá trị byte đệm ($pad\_val$) Số lượng byte thêm vào Độ dài sau đệm
10 bytes 0x06 6 bytes 0x06 16 bytes (1 block)
15 bytes 0x01 1 byte 0x01 16 bytes (1 block)
16 bytes (Đã tròn khối) 0x10 (16 thập phân) 16 bytes 0x10 (Bắt buộc!) 32 bytes (2 blocks)

2.2. Triệt Tiêu Tấn Công Padding Oracle (Bleichenbacher / Vaudenay)

Nếu hàm giải đệm dừng ngay lập tức (break / early-return) khi gặp byte đệm sai, kẻ tấn công có thể đo thời gian phản hồi (Time-Leakage) để giải mã toàn bộ bản mã mà không cần biết khóa AES.

Trong core/padding.c, hàm pkcs7_unpad kiểm tra toàn bộ vùng đệm mà không trả về lỗi phân biệt:

core/padding.c - Kiểm định đệm PKCS#7 
uint8_t pad_val = in[in_len - 1];
if (pad_val == 0 || pad_val > block_size || (size_t)pad_val > in_len) {
    return PKCS7_ERR_INVALID_PADDING;
}

// Duyệt kiểm tra mọi byte trong khối đệm
for (size_t i = in_len - pad_val; i < in_len; i++) {
    if (in[i] != pad_val) {
        return PKCS7_ERR_INVALID_PADDING;
    }
}
size_t unpadded_len = in_len - pad_val;
memcpy(out, in, unpadded_len);
return (int)unpadded_len;

03. Cầu Nối Bộ Nhớ Ctypes (Zero-Copy Buffer Interop)

Tại engine/wrappers/aes_wrapper.py, việc giao tiếp với thư viện động (aes128.dll / libaes.so) đòi hỏi quản lý chính xác con trỏ bộ nhớ:

  • Khởi tạo buffer đầu ra: Cấp phát trước bộ nhớ C bằng (ctypes.c_uint8 * padded_len)().
  • Chuyển đổi dữ liệu Python sang mảng byte C: Sử dụng (ctypes.c_uint8 * in_len).from_buffer_copy(plaintext), đảm bảo an toàn con trỏ và không bị garbage collector thu hồi giữa chừng.
  • Khai báo con trỏ: ctypes.POINTER(ctypes.c_uint8) cho cả input, output, key và IV.

04. Kiến Trúc Mạng Feistel Hai Vòng Trong RSA-OAEP

Khóa phiên AES (16 bytes) được bọc bằng RSA-OAEP (Optimal Asymmetric Encryption Padding) tuân thủ RFC 8017.

4.1. Công thức giới hạn dung lượng bản rõ trong RSA-2048 OAEP

$$M_{max} = k - 2 \cdot hLen - 2$$

Với khóa RSA 2048-bit ($k = 256$ bytes) và hàm băm SHA-256 ($hLen = 32$ bytes):

$$M_{max} = 256 - (2 \times 32) - 2 = 190 \text{ bytes}$$

Vì Session Key AES-128 chỉ dài đúng 16 bytes, nó hoàn toàn nằm trong ngưỡng an toàn 190 bytes của RSA-OAEP.

4.2. Quá trình Biến Đổi Feistel Hai Vòng

+------------------+-----------------------------+
|    seed (32B)    |            DB               |  DB = Hash(L) || PS || 0x01 || M
+------------------+-----------------------------+
         |                        |
         |           +---------[ MGF1 ]
         |           |            |
         |           v            |
         |--------> (+) --------> |  maskedDB = DB XOR MGF1(seed)
         |                        |
      [ MGF1 ] <------------------+
         |
         v
        (+) <--------------------------------- seed
         |
         v
    maskedSeed = seed XOR MGF1(maskedDB)

=> Encoded Message: EM = 0x00 || maskedSeed || maskedDB

Byte đầu tiên luôn là 0x00 để đảm bảo giá trị số nguyên $EM$ luôn nhỏ hơn Modulus RSA ($EM < n$), ngăn ngừa lỗi tràn modulo trong phép toán $c = m^e \pmod n$.

05. Lược Đồ Chữ Ký Xác Suất RSA-PSS

Tại engine/signer.py, việc bảo vệ tính toàn vẹn bản mã được thực hiện bằng RSA-PSS (RFC 8017).

5.1. Khác biệt cốt tử giữa RSA-PSS và RSA PKCS#1 v1.5

  • RSA v1.5: Chữ ký mang tính tất định (Deterministic). Nếu ký 2 lần cùng 1 file, chữ ký giống nhau hoàn toàn $\rightarrow$ Dễ bị phân tích cấu trúc toán học.
  • RSA-PSS: Chèn một chuỗi muối ngẫu nhiên (Salt có độ dài bằng digest SHA-256 = 32 bytes). Mỗi lần ký cùng một file sẽ sinh ra một chuỗi chữ ký hoàn toàn khác nhau.
  • Đạt tiêu chuẩn an toàn toán học cao nhất: EUF-CMA (Existential Unforgeability under Chosen Message Attack).

06. Chuẩn Xác Thực Web3 EIP-191 & Chống Tấn Công Replay

Khi Người nhận (Buyer) yêu cầu rút tệp, hệ thống không dùng mật khẩu mà sử dụng chữ ký số đường cong elliptic **SECP256K1** (EIP-191).

6.1. Cấu trúc thông điệp chuẩn mực (SIWE Challenge)

"\x19Ethereum Signed Message:\n" + len(message) + "CloakShare Retrieve Auth: <tx_id> @ <timestamp>"

Tiền tố \x19Ethereum Signed Message:\n ngăn chặn kẻ xấu lừa người dùng ký vào một giao dịch chuyển tiền On-Chain độc hại!

6.2. Thuật toán kiểm tra giới hạn thời gian (Time Drift)

engine/wallet_auth.py - Chống Replay Attack 
@classmethod
def verify_retrieve_request(cls, tx_id: str, address: str, timestamp: int, signature_hex: str) -> bool:
    current_time = int(time.time())
    # Giới hạn trôi lệch đồng hồ tối đa 60 giây
    if abs(current_time - timestamp) > cls.MAX_CLOCK_DRIFT:
        return False
    msg = cls.create_retrieve_message(tx_id, timestamp)
    return cls.verify_signature(address, msg, signature_hex)

08. Quản Lý Bộ Nhớ Heap & Cơ Chế Memset Zeroize

Một trong những khác biệt kỹ thuật sâu sắc nhất của CloakShare là cách xử lý bộ nhớ trong tiến trình Python:

8.1. Tại sao đối tượng `str` và `bytes` không an toàn?

Trong CPython, đối tượng str và bytes là bất biến (Immutable). Khi ta gán biến bằng None hoặc gọi del, Python chỉ giảm biến đếm tham chiếu (Reference Count). Vùng nhớ vật lý chứa dữ liệu nhạy cảm vẫn còn nguyên trên RAM cho đến khi trình thu gom rác (Garbage Collector) tái cấp phát, tạo cơ hội cho kẻ tấn công trích xuất RAM (Memory Dump).

8.2. Giải pháp `bytearray` và hàm `_wipe()`

CloakShare lưu toàn bộ payload nhạy cảm bằng kiểu bytearray (Mutable C buffer). Hàm _wipe() duyệt trực tiếp từng phần tử và ghi đè byte 0x00:

broker/memory_store.py - Ghi đè bộ nhớ vật lý 
def _wipe(value: Any) -> None:
    """Ghi đè nội dung một bytearray bằng byte 0x00 (tương đương memset trong C)."""
    if isinstance(value, bytearray):
        for i in range(len(value)):
            value[i] = 0

def _purge_one(self, tx_id: str) -> bool:
    entry = self._data.pop(tx_id, None)
    if entry is None:
        return False
    for field in ("iv", "wrapped_key", "ciphertext", "signature"):
        _wipe(entry.get(field))
    entry.clear()
    return True
